# GameFit 日本語UIコピーガイド

日本のPC・ゲームユーザーに「詳しい友人が、根拠を持って冷静に教えてくれる」と感じてもらうための基準です。新しい画面や状態を追加するときは、この文書と `ui-copy-ja.js` を確認します。

## トーン

- 本文は「です・ます」。ボタンと短い見出しは簡潔な体言止めでもよい。
- 結論 → 主な理由 → 必要な人向けの詳細、の順に置く。
- 購入を急がせない。「今のままでよい」「先に設定を確認」「今回は避ける」も正式な結果にする。
- 「あなたに最適」「高精度」「実証済み」「究極」「完璧」など、実績や根拠を超える表現は使わない。
- 内部のスコア、ID、enum、モデル名をそのまま表示しない。

## 判定名

判定ロジックでは英語enumを維持し、画面では `ui-copy-ja.js` の表示名を使います。

| 内部enum | 表示名 |
| --- | --- |
| `SAFE / FAMILIAR` | 今の機材に近い仕様の候補 |
| `BETTER_FIT` | 登録した好みとの一致が比較的多い候補 |
| `VALUE_ALTERNATIVE` | 条件に近く価格を抑えやすい候補 |
| `EXPLORE` | 条件を確認しながら比べたい候補 |
| `AVOID` | 今回は避けた方がよさそう |
| `DONT_UPGRADE` | 今は買い替えを急がなくてよさそうです |
| `CLARIFY` | もう少し情報が必要です |

## ボタン・状態・エラー

- ボタン名は、押した直後に起きることを示す。「削除」「書き出す」「候補を見直す」のように動詞で終える。
- 削除対象を明記し、「すべて」で異なる保存領域をまとめない。
- 完了メッセージは「何が」「どこに」保存・削除されたかを示す。
- エラーは内部例外を表示せず、結果と次の行動を一文で伝える。
- `CLARIFY` では不足情報と、利用者が次に行うことを必ず示す。
- 空状態、読込不可、壊れた保存データ、保存領域が使えない状態も通常の画面文言として用意する。

## Privacy・広告・根拠

- Privacyは技術名ではなく、保存場所、外部送信の有無、共有端末での注意、削除方法を説明する。
- 実装より強い保存期間や自動削除を約束しない。
- 計測する画面では、送信項目、送信先、送信しない項目を説明する。
- 広告リンクの有無を明示し、報酬の有無で診断結果や掲載順を変えない。
- 「公式」は公式情報源そのものに限る。GameFitの目標値や比較は「この簡易診断の目安」とする。
- 外部記事やレビューの本文、画像、表、グラフ、サムネイルを転載しない。

## 追加時の確認

1. `ui-copy-ja.js` で内部値と表示名を分離したか。
2. デスクトップと390pxで、長い日本語、ボタン、カード、表が切れないか。
3. 表示名を変えてもevent名、enum、KPI、テスト用selectorが変わっていないか。
4. 購入後実績がないのに、精度や信頼性を断定していないか。
5. Privacy、広告、削除、計測の説明が実装と一致しているか。
